# Coding Best Practices & Reminders

> **Style rule:** Notes must be clear and concise — 300 characters or less each. Group by topic, not by date. Whenever a PR review (CodeRabbit or human) catches a mistake, add or amend a note here right away so it isn't repeated.

## Python Style & Error Handling

- **An `if`/`elif` chain over related-but-independent fields needs a branch for every combination that can actually occur, or one silently does nothing.** (CodeRabbit, PR #341) Settings dialog's JobBOSS credential save had `if new_password and new_user: save` / `elif new_user changed: carry forward`, with no branch at all for "password entered, username blank" -- that combination just fell through both conditions and the password was silently discarded with zero user-visible feedback, no error, no indication it wasn't stored. When enumerating branches over 2+ independent boolean-ish inputs, explicitly check: is there a combination that reaches neither branch? If so, does falling through silently there actually mean "nothing to do," or does it mean "user action needed and got dropped"?
- **Hoist helper functions out of methods.** Defining a helper (e.g. `_is_hidden`) inside a method recreates it on every call — move it to module or class level.
- **Avoid broad `except Exception`.** Catch specific exceptions (`OSError`, `AttributeError`, `shutil.Error`, etc.) so unexpected errors aren't silently masked.
- **Don't leave silent `except Exception: pass`.** Log at debug/warning level so failures stay traceable without breaking the fallback behavior.
- **This repo has no logging config anywhere (no `basicConfig`/handlers).** Default root level is WARNING, so `logger.debug(...)` never fires at runtime. Use `logger.warning` (or higher) for anything that should actually be visible until real logging setup exists.
- **Drop f-string prefixes with no placeholders.** Ruff flags these (F541); use plain string literals instead.
- **A hardcoded `if entry_type == 'x':` special-case silently drops every other type.** `add_to_history()` only had a `'job'` branch though the plugin template documents it as a generic mechanism; quote entries vanished with no error. Prefer a generic `history[f'recent_{entry_type}s']` keying over enumerating known types, or add an explicit `else: log a warning`.
- **Escape backslashes in non-raw docstrings.** A bare backslash (e.g. `runtime\python.exe`) is an invalid escape sequence.
- **Grep-based dead-code checks give false positives on dynamic dispatch and Qt overrides.** `main.py`'s `populate_customer_lists()` calls `populate_*_customer_list` methods via `dir()`/`getattr()` naming convention, not a literal call site; `dragEnterEvent`/`closeEvent`-style Qt overrides are invoked by the framework, not Python source. Verify a method has no *reachable* caller (including reflection/framework dispatch) before removing it as dead code.
- **When gating a fix on "is this the genuinely ambiguous case," check every condition that makes it ambiguous, not just the one you noticed first.** (CodeRabbit, PR #316, catching my own prior fix) A legacy-vs-PO-container disambiguation checked only one of three variables that jointly determine ambiguity — it false-positived on real PO folders whenever an unchecked variable happened to coincide with the checked one.
- **Config overrides (env vars, CLI flags, etc.) should apply per-field, not all-or-nothing against a base config.** (CodeRabbit, PR #343) `tools/dump_db_schema.py`'s `_load_settings()` used to return *either* every `JOBBOSS_DB_*` env var *or* all of `settings.json`, whole — setting just `JOBBOSS_DB_PASS` (the documented way to run the tool with a different login) silently blanked `HOST`/`PORT`/`NAME`/`USER` too, since the "env mode" branch read each from a possibly-unset env var with no fallback. Fixed by loading the base config first, then layering each override field independently (`if value: settings[key] = value`), so setting one override never blanks the rest.

## File & Directory Operations

- **`shutil.copy2` overwrites silently — check existence first.** Guard with `if not dest.exists()` before copying; `FileExistsError` handlers around `copy2` are dead code since it never raises that.
- **Sort directories before files in listings.** Use `key=lambda n: (not os.path.isdir(...), n.lower())` so dirs come first, matching OS file-browser conventions.
- **Wrap directory scans in `OSError`/`PermissionError` handlers.** Log per-item/per-dir and continue — never let one bad entry abort discovery (e.g. plugin dir scans).
- **Use atomic swap for install/update operations.** Copy to a temp dir, then backup-then-rename into place, with rollback on failure, so a partial write never corrupts the live install. Same applies to any JSON persistence (settings/history): `open(path, 'w')` truncates before writing, so a crash mid-write leaves an empty/corrupt file. Use `shared.utils.atomic_write_json()` (write to a same-dir temp file, `os.replace()` into place) instead.
- **Gate link creation on copy success.** In "copy then link" flows, track a `*_ready` flag; only create the link if the copy succeeded or the destination already existed.
- **`tempfile.mkstemp()` hardcodes `0o600` on POSIX, ignoring umask.** After `os.replace()` swaps it into place, this silently narrows a shared file's permissions. `os.chmod()` the temp file first — to the original file's mode if it exists, else `0o666 & ~umask` — before replacing. Also `os.fsync(fd)` before `os.replace()`: the rename alone is torn-write-safe but not crash-durable.
- **Probe umask with a throwaway file, not `os.umask()`.** `os.umask()` briefly mutates the process-wide mask to read it, racing any other thread creating a file in that window. Create a uniquely-named file with `O_CREAT|O_EXCL` and inspect its resulting mode instead.
- **Check `create_file_link`'s boolean return at every call site.** It returns `False` on failure instead of raising; ignoring it (or incrementing a success counter unconditionally) reports failed links as successful adds in a windowed GUI app with no visible console.
- **Don't check path containment with `str.startswith()`.** (CodeRabbit, PR #315, recurred at PR #334) Windows paths are case-insensitive and `realpath()` doesn't normalize case; a bare string prefix also misclassifies a sibling like `"ITAR-jobs"` as being under `"ITAR"`. Use `os.path.normcase()` on both sides, then `os.path.commonpath([a, b]) == b`; catch `ValueError` (raised for paths on different drives) and treat it as "not contained," not an error. This exact bug class recurring in a brand-new call site (`modules/job/module.py`'s ITAR classification) despite already being logged here means "grep CODING_NOTES for the pattern before writing a new path-comparison" is worth doing proactively, not just reactively after a review catches it.
- **`mkdir(exist_ok=True)` can't tell "I created this" from "it already existed" — don't use it as a uniqueness/reservation check.** (CodeRabbit, PR #317 promotion review) Two racing callers (e.g. two workstations on a shared network drive) both get a truthy result and both proceed as if they'd won. A prior duplicate-check *scan* narrows a create race but can't close it — the actual reservation has to happen at the `mkdir()` call itself. Use a bare `mkdir()` (no `exist_ok`) and catch `FileExistsError` locally, at the exact call site, not the method's outer generic exception handler — otherwise a benign lost race surfaces as a modal error dialog instead of a distinguishable duplicate.
- **A reservation `mkdir()` isn't the end of the story — roll it back if the setup work after it fails.** (CodeRabbit, PR #320, catching a gap in the fix directly above) `create_single_job()` reserved `job_path` before file processing, history, and index updates; if any of those raised, the folder was left behind half-initialized, and a retry hit the new `FileExistsError` guard and was told "duplicate" for a job that was never actually completed — no way to finish it or recover its records. Wrap the post-reservation work in its own `try`/`except Exception: shutil.rmtree(reserved_path, ignore_errors=True); raise` so a later failure un-reserves the path instead of stranding it. Also note: an `mkdir()`-based reservation only catches an *exact* path collision — if the reserved path is built from free-text fields (e.g. `{job_number}_{description}`), two racing callers with the same logical key but different free text won't collide at all. Out of scope for the fix above (the original finding asked to close the exact check-then-create race, not redesign the identity key), but worth flagging as a known, separate gap before relying on this pattern for a truly free-text-independent uniqueness guarantee.
- **Rolling back a filesystem reservation must also undo any shared in-memory state mutated before the failure, not just the filesystem.** (CodeRabbit, PR #320, a second gap in the same rollback) `add_to_history()` mutates the shared `history['recent_jobs']` list *before* `save_history()` runs; when `save_history()` failed and the handler above rolled back only `job_path`, the stale history entry survived and made `_check_duplicate_job()` (which checks `recent_jobs` first) report the just-rolled-back job as a duplicate on retry — worse than the original bug, since now the folder doesn't even exist to explain why. Identify and remove the specific entry the failed attempt added (e.g. by its unique `path`) inside the same rollback handler.
- **Accepted residual gap (PR #320): the in-memory history rollback above doesn't retroactively un-persist an already-successful `save_history()` disk write.** If `search_index.add_job()` raises *after* `save_history()` already wrote the entry to `history.json`, the in-memory rollback removes it for this session but the stale entry survives on disk until the next real save — requires a non-`sqlite3.Error` exception escaping `add_job()`'s own internal catch, right after a successful disk save. Not chased further; full transactional consistency across the in-memory dict, `history.json`, and the SQLite index for that exact interleaving is more machinery than warranted here.
- **Only require a resource for the destination branch that actually uses it.** (CodeRabbit, PR #331) `add_files_to_job()` fetched `bp_dir` and skipped the job unconditionally when it was unset, even for `dest == 'job'`, which never touches the blueprints dir — a job-only add silently failed just because blueprint storage wasn't configured. Move the resource lookup/requirement inside the `if dest in (...)` branch that needs it.
- **When a multi-job/multi-item loop skips one item, don't clear the caller's pending-input state as if everything succeeded.** (CodeRabbit, PR #334) `add_files_to_job()` called `clear_add_files()` whenever *any* file was added, even if a mixed selection had a job skipped for missing `bp_dir` — the skipped job's files vanished from `self.add_files` with only a log line, forcing the user to re-add everything to retry. Track skipped items by name, surface them in a dedicated dialog, and only clear pending state when nothing was skipped.
- **A per-item `mkdir()`/filesystem call inside a multi-item batch loop needs its own try/except, not just the surrounding items' error handling.** (CodeRabbit, PR #334, a second gap in the note directly above) `customer_bp.mkdir(parents=True, exist_ok=True)` for one job in a multi-select batch was uncaught — a `PermissionError` there would crash the whole method instead of skipping just that job and continuing with the rest. Catch `OSError` (not just `PermissionError`) at the exact call site and route into the same skipped-jobs tracking as other skip reasons in the same loop.
- **When a batch loop can skip an item for multiple distinct reasons, tag each skip with its reason instead of collapsing them into one tracking list.** (CodeRabbit, PR #340, a third gap in the two notes above) The skipped-jobs dialog reported every skip as "blueprints directory not configured," even a `mkdir()` failure where the directory *was* configured and just couldn't be created (permissions, disk full) — actively misdirecting troubleshooting toward a non-existent config problem. Store `(name, reason)` pairs and build a distinct message per reason.

## ITAR / Filter Consistency (JobDocs)

- **Search must mirror browse/refresh filter logic.** `search_jobs`/`search_quotes` need the same customer + ITAR filtering as `refresh_*_tree`, or search results silently ignore active filters.
- **Detect ITAR prefixes consistently.** Use `startswith(('[ITAR] ', '[ITAR-BP] '))` everywhere a customer label is checked, not a bare `'[ITAR]'` substring.
- **A restricted-access build (e.g. a search-only kiosk) must exclude ITAR directories from search/indexing entirely, not just label them.** Gate every dir-discovery helper on `is_readonly()`, and also filter query results by the same ITAR-prefix check as defense-in-depth against a stale local index from before the machine was reconfigured.
- **Cancel the active tree worker before a synchronous search.** Otherwise queued `customer_loaded` emissions can repopulate the tree after the search clears it, mixing stale and fresh results.
- **Lazy top-level QTabWidget construction needs a force-build hook for the initially-shown tab.** `setCurrentIndex()` only emits `currentChanged` if the index actually changes — the tab that's already current at startup (or after a CLI-prefill tab switch) never fires it. Call the build handler explicitly for the current index after any programmatic `setCurrentIndex()`.
- **Don't remove a lazy-construction item from its pending/retry tracking dict until the build actually succeeds.** Popping before the `try` around `get_widget()` permanently bricks that tab as a blank placeholder if construction fails once; pop only in the success path so a later click can retry.
- **Track a lazily-built widget's "is it built" state with an explicit flag the caller sets, not by inferring it from the module's own internal caching.** A `get_widget()` contract only promises a returned `QWidget`, not that the implementation caches it to `self._widget` — a plugin that builds fresh each call would always read as "not built" otherwise.
- **Defer a sub-tab's expensive data load until it's actually shown.** `refresh_job_tree`/`refresh_quote_tree` used to walk the whole customer directory tree as soon as the widget was built (via the `populate_*_customer_list` dynamic dispatch). Gate the walk on `<sub_tab_widget>.currentWidget() is <target_tab>`, set a stale flag when skipped, and flush it from `currentChanged` when the tab becomes active.
- **Excluding a directory from search/indexing isn't enough if the UI also lets a user browse into an arbitrary subfolder.** (CodeRabbit, PR #315) A junction/symlink under a permitted folder can target the excluded directory; `os.listdir`/`isdir` follow it transparently. Reject reparse points during traversal, and re-check the canonical (`realpath`) path against permitted roots at every open/copy/print, not just at discovery. **This includes the recursion's own root, not just entries it lists** — my first pass filtered a directory's *children* before listing them, but the first call itself (fed a live/index search result's path directly, not one that passed through the filter) skipped validation entirely; a stale index entry or reparse point could still get `os.listdir()`'d and displayed before the child-level filter ever ran.
- **A symlink/reparse-point exclusion added to the UI-facing traversal doesn't automatically cover search/indexing — they're separate `os.listdir()`-based traversals over the same directories.** (CodeRabbit, PR #315) `os.walk()`'s `followlinks=False` default already skips descending into a symlink found *mid-walk*, but not one passed as its own top-level argument — so a "customer" folder built from an unfiltered `os.listdir(base_dir)` listing and then handed to `os.walk(customer_path)` still gets fully walked and indexed. Fix at the source (`is_reparse_point()` moved to `shared/utils.py`, checked once inside `AppContext.find_job_folders()`/`find_quote_folders()` so every caller — live search and indexing alike — inherits the guard) *and* at each customer-listing call site before a path is ever constructed from it.
- **A reparse-point check must fail closed on API failure, not fall through to a weaker one.** (CodeRabbit, PR #315) `is_reparse_point()` fell back to `os.path.islink()` whenever `GetFileAttributesW` returned `INVALID_FILE_ATTRIBUTES` or raised — but `islink()` doesn't detect Windows junctions/mount points, so a lookup failure silently let one through. On `nt`, treat any lookup failure as a reparse point (fail closed); only use `islink()` on non-Windows.

## Qt / PyQt6 UI Patterns

- **Disable built-in expand-on-double-click before adding a custom handler.** `QTreeWidget` toggles expand state itself; a slot that also calls `setExpanded(not isExpanded())` double-inverts it. Use `setExpandsOnDoubleClick(False)` + `itemFromIndex(index)`.
- **Wrap `QPainter` usage in try/finally.** An exception mid-render skips `painter.end()`, leaving the print backend in an inconsistent state.
- **Cross-thread signals need a real `QObject` receiver.** A plain function connected to a `QThread` signal runs on the worker thread; use a `QObject` with `@pyqtSlot` methods so Qt queues delivery to the main thread.
- **Stream results per-item instead of buffering all in memory.** Emit one `page_ready(QImage)` per page rather than building the full list first, to avoid exhausting memory on large documents.
- **Always emit a "done" signal from try/finally.** If an exception escapes a worker's `run()`, the receiver can wait forever for completion.
- **Block dialog Save/Cancel/close during an in-flight async operation.** Otherwise the user can race a background worker callback against disposed UI state. Applies equally to a manual `QApplication.processEvents()` loop on the GUI thread, not just real `QThread` workers — override `closeEvent`/`reject()` to ignore while a busy flag is set.
- **A close-block needs an escape hatch, or it trades a crash for an unkillable hang.** Blocking `closeEvent`/`reject()` unconditionally with no Cancel control leaves zero way out if the in-flight work stalls (e.g. filesystem I/O against a dead network share) or pops a blocking error dialog per failed item. Add a Cancel button that sets a flag checked between work units, and guard `done()` too (the choke point `accept()`/`reject()` both funnel through) so a future `QDialogButtonBox` can't silently bypass the guard.
- **Persist settings through the real settings store, not a dialog-local copy.** Writing to `self.settings` inside a dialog is lost on Cancel if that object is a local copy rather than the live settings store.
- **`QTextDocument.print_()` was renamed to `print()` in PyQt6** (the trailing underscore was a PyQt5 workaround to avoid shadowing Python 2's `print` statement, not needed in Python 3). Calling `.print_()` raises `AttributeError` at runtime, not an import-time or lint-time failure — caught only by actually exercising the print/PDF path, not by reading the PyQt5-era examples still common online.
- **A literal `--` anywhere inside a `.ui` file's `<!-- -->` XML comment breaks the whole file**, not just at the boundary — PyQt6's `uic.loadUi()` fails with a bare `not well-formed (invalid token)` ElementTree error that doesn't name the offending line as clearly as a normal XML parse error does. Hit twice in `modules/reporting/ui/reporting_tab.ui` already (an em-dash-style `--` used as a sentence separator in an explanatory comment). Before adding prose to a `.ui` comment, either avoid `--` entirely or verify with `python -c "import xml.etree.ElementTree as ET; ET.parse('path/to/file.ui')"` before trusting `uic.loadUi()` to load it.
- **Escape untrusted strings before interpolating into RichText labels.** A crafted version string could inject HTML into a `QLabel`; use `html.escape()`.
- **Keep a live reference to non-modal dialogs.** Store on a longer-lived owner (e.g. `window._dialog = dlg`) and clear it on `finished`, or the dialog is garbage-collected and disappears immediately.
- **`QMimeData.data()` has no `FORMATETC.lindex` — it can only ever retrieve entry 0 of a multi-item OLE virtual-file drag (`FILEGROUPDESCRIPTOR` + `FileContents`).** Parse and log every entry the descriptor lists (documented fixed-size struct, safe to loop), but warn the user explicitly when count > 1 instead of silently emitting only the first file as a full success.
- **A "one row = one item" MIME payload used for single-select must be re-audited when multi-select is possible.** Classic Outlook's drag data mirrors this (`text/plain` header+rows, `Csv` entry IDs) — code that only reads line/entry 0 silently drops every other selected item with no error.
- **A loop that saves N items must track per-item success, not just `if not results: warn()`.** Checking only whether the aggregate result is empty misses partial failure (e.g. 4 of 5 items retrieved) — the same silent-partial-failure bug class the loop itself was written to fix. Collect failures by name/index and warn for any non-empty-but-incomplete result, mirroring the all-or-nothing check rather than replacing it.
- **Never `zip()`/index-pair two independently-filtered parsed lists without checking their lengths match first.** If two MIME/format blobs are decoded by separate filter rules (e.g. `Csv` entry IDs vs. `text/plain` subjects), a single divergent row silently shifts every pairing after it. On a length mismatch, log both lengths and drop the non-authoritative list rather than guess — a wrong positional pair can feed a search/lookup with the wrong key and silently return the wrong record.
- **Descriptor/attachment filenames from an OLE drag source are untrusted input.** Sanitize with `os.path.basename()` before joining into a temp dir — an unescaped `../` or absolute path in a `FILEGROUPDESCRIPTOR` entry is a path-traversal vector, not just a display string.
- **Never call a modal `QMessageBox` synchronously from inside `dropEvent()`.** Windows OLE drag-drop runs its own nested event loop for the duration of the drop; a synchronous modal there can hang or crash. Defer with `QTimer.singleShot(0, lambda: QMessageBox.warning(...))` so it shows after the drop handler returns.
- **`QImageReader.setScaledSize()` only bounds decode memory for formats whose Qt plugin supports it — verify with `supportsOption(ScaledSize)`, don't assume.** True for JPEG on this Qt build; False for PNG/BMP/WEBP/ICO/GIF, where Qt still decodes full-res internally then scales down in software (same peak memory as `QPixmap(path)`). Still worth using: it bounds *steady-state* memory for every format (no full-res `QPixmap`/`QImage` held resident afterward), just not decode-time memory for non-native formats. A real decode-time fix for those would need a different library (e.g. Pillow, not currently a dependency) — don't claim "bounded decode" without checking `supportsOption()` for the specific format first.
- **A mode flag (e.g. `readonly_mode`) only enforces anything once it's on `AppContext`, not just `main.py`.** Skipping module *loading* isn't a write guarantee — audit every still-loaded module's write paths and gate each on `app_context.readonly_mode`.
- **`QMimeData.formats()`'s ordering between format variants (e.g. ANSI vs. Unicode `FileGroupDescriptor(W)`) isn't guaranteed by Qt.** (CodeRabbit, PR #316) Picking the first substring match can select the ANSI format even when Unicode was also offered, truncating filenames at the first null byte. Explicitly prefer the better variant; don't rely on list order.
- **A full Qt MIME identifier like `application/x-qt-windows-mime;value="FileGroupDescriptorW"` ends with a closing quote, not the format's own suffix.** `fmt.endswith('W')` silently never matches it — match a lowercased token/substring instead of relying on string-end position.
- **Once a `logger.debug()` call is backed by a real persistent file handler (not just a no-op default config), audit what it logs.** (CodeRabbit, PR #316) A diagnostic log line emitting the full dropped-files list — paths often derived from Outlook email subjects — becomes a standing privacy leak once `RotatingFileHandler` makes it durable on disk. Log counts/shapes, not full untrusted content, once logging actually persists.
- **`subprocess.Popen(["explorer", f"/select,{path}"])` (list form) silently opens the default library instead of selecting the target whenever `path` contains a space.** (found post-merge, PR #328 — user report: "double-clicking opens my documents") Python's list-form quoting wraps the *entire* `/select,<path>` token in quotes once it sees a space, but explorer's own command-line parser only understands the path itself quoted, with `/select,` left bare (`/select,"C:\Path\New folder"`) — the exact kind of space-containing name (`"New folder"`, `"PO 1001"`) this specific feature exists to flag. Pass a single command-line **string** to `Popen` instead of a list so Python doesn't re-quote it: `subprocess.Popen(f'explorer /select,"{norm_path}"')`. Safe from injection since `"` is not a legal character in a Windows path. `open -R` (macOS) and `xdg-open` (Linux) don't have this quirk — list form is fine there.
- **A kiosk/read-only UI must block every path to Explorer, not just the obvious menu item.** "Open" on a directory via `QDesktopServices.openUrl` launches Explorer on Windows, and "Copy Path" hands the user a pasteable address. Audit double-click handlers too, not just context menus — they often route to the same action without going through the menu's guard.
- **"Open in viewer" isn't enough on a kiosk build — the external app's own Save As / Recent Files leaks the real path.** (user finding, screenshot of Foxit's Save As showing the full network path) `QDesktopServices.openUrl` on the real file hands a trusted-looking app full knowledge of where it lives. Copy to a temp dir first and open that; clean up via `atexit` (mirrors `shared/widgets.py`'s `_dropzone_tmp_dirs`), since there's no reliable way to detect "the external viewer closed."
- **An `atexit`-only cleanup for per-open temp copies leaves them all on disk for the entire session, not just until the viewer closes.** (CodeRabbit, PR #317 promotion review, on the note directly above) A kiosk left running for days accumulates one plaintext copy of every customer document ever viewed. Since there's still no way to detect "the viewer closed" this session, clean up the *previous* copy right before making the next one instead — only the most-recently-viewed file's copy exists on disk at any time, with the `atexit` handler as the fallback for whichever one is open when the process exits.
- **`shutil.rmtree(ignore_errors=True)` can silently fail (e.g. a file the external viewer still has open, on Windows) — don't drop that path from tracking just because you attempted removal.** (CodeRabbit, PR #317 promotion review, a second gap in the note directly above) Popping a path off the tracking list *before* confirming `rmtree` actually removed it forgets a failed deletion forever — worse than the original bug, since now neither the next open's cleanup nor the `atexit` fallback will ever retry it. Check `os.path.exists()` after the `rmtree` attempt and keep only the paths still present, so a failed removal is retried on the next cleanup call instead of leaking permanently.
- **When "fixing" a doc/comment accuracy claim, verify the *actual gating condition* in code, not just whether the referenced code exists.** (CodeRabbit, PR #317 promotion review, catching my own over-correction) I found `core/settings_dialog.py` gets copied into the Kiosk installer's `[Files]` list and concluded the Settings dialog was "present and reachable" — but missed that `main.py` only calls `setup_menu()` (which builds the File menu containing the Settings action) `if not self.readonly_mode`, so the Kiosk menu bar is never constructed at all. The original claim ("no Settings UI") was actually correct about UI reachability; only "never installed" (about the file's presence on disk) was wrong. Trace the actual runtime gate (the call site's condition), not just whether a file/class exists somewhere in the tree.
- **Removing a lazily-built tab's placeholder widget via `QTabWidget.removeTab()` doesn't free it — call `deleteLater()` on the removed widget too.** (CodeRabbit, PR #315, on pre-existing PR #306 lazy-tab code — logged per policy, not fixed there since it's out of this branch's scope) `main.py`'s `_on_tab_activated()` swaps the placeholder for the real widget but never disposes of the old one.
- **`worker.cancel(); worker.wait()` on the GUI thread freezes the app for as long as the worker takes to notice cancellation — unbounded if it's stuck inside a single hung syscall.** (CodeRabbit, PR #317 promotion review) `is_cancelled()` polling *around* a blocking call (e.g. `os.listdir()` on a dead network share) can't interrupt that one call. Make `cancel()` non-blocking (never call `.wait()` from a GUI-thread slot) and have the worker's `finished` signal fire unconditionally — cancelled or not — so a caller can defer starting replacement work until `finished` confirms the old worker actually stopped, instead of relying on a synchronous wait to know. Mirrors `modules/search/module.py`'s `SearchWorker`/`cancel_search()`, but **that pattern's own `cleanup()`/`clear_search()` deliberately keep the blocking `wait()`** — module teardown can't proceed with a background thread still touching about-to-be-destroyed widgets/`app_context`, so don't convert every `cancel()+wait()` in a file uniformly; only the interactive/GUI-triggered ones.
- **A worker whose `finished` fires unconditionally must not be reassigned to a new instance while the old one might still be running.** (would-be race, avoided by construction) If a "cancel now, restart later" design pre-constructs the replacement worker before the old one's `finished` arrives, that late signal can land on state meant for the new one. Simplest safe shape: never assign `self._worker` to a new instance except from inside the `finished` handler itself (after re-entering the same start-method, which checks `isRunning()` first) — since the old worker's own `finished` is what triggers that call, there's only ever one worker in flight, and no stale-signal window exists.
- **Don't declare a class-level `finished = pyqtSignal()` on a `QThread` subclass and emit it manually as the last line of `run()` — use the inherited `QThread.finished` instead.** (CodeRabbit, PR #321, catching a subtle bug in the note directly above) A manually-emitted custom signal is a queued cross-thread delivery; Qt's own event loop can process it *before* the thread has actually finished returning from `run()`, so a connected slot isn't guaranteed to see `isRunning() == False` yet — proven with a repro pairing `QThread.msleep()` after `emit()` with an event-loop check inside the slot. A "defer restart until `isRunning()` is False" design built on that assumption can re-defer forever against a worker that will never signal completion again. `QThread.finished` (undeclared, just don't shadow it) is specced by Qt to fire only after `run()` has truly returned — a plain identity check (`'finished' not in Worker.__dict__` / `Worker.finished is QThread.finished`) is a reliable, non-flaky regression test for this, since the timing race itself is too narrow to reproduce deterministically without an artificial delay.
- **A "deferred action, run once the stale worker stops" design must re-check every guard the immediate call path checks — not just the ones the immediate path happened to check first.** (CodeRabbit, PR #321, a second gap in the same fix) `refresh_job_tree()` checks tab-active state before starting work; `search_jobs()` never did (nothing to defer against, previously). Once `search_jobs()` itself became a deferrable pending action, it inherited a way to run *later*, by which point the user may have navigated away — but it still had no tab-active guard, so a deferred search could run its full synchronous, unbounded traversal against a tab nobody can see. Give every method that can end up as a deferred action the same "am I still relevant" check the synchronous entry points already have, not just the one that happened to be written first.
- **Every new `QThread` worker whose per-item scan can run long must thread `is_cancelled` into `find_job_folders()`/similar itself, not just check a flag between top-level items.** (CodeRabbit, PR #325) This exact gap — already fixed once for `JobTreeWorker`/`QuoteTreeWorker` (`tests/test_tree_walk_cancellation.py`) — recurred verbatim in a brand-new `FolderNamingCheckWorker` that simply forgot to pass `is_cancelled` at all. Copy the whole pattern (arg + `cleanup()` cancel-and-wait + a slow-fake-context test proving `cancel()+wait()` returns quickly mid-scan), not just the worker skeleton, whenever a new worker calls this method.
- **A cancelled worker's partial results must be marked as partial in its own completion payload, not left for the caller to guess.** (CodeRabbit, PR #325) `FolderNamingCheckWorker.finished` originally emitted only the results list; a scan cancelled mid-sweep still emitted whatever it had collected so far, and the UI slot couldn't tell that from a genuinely complete zero/low-result scan — showing "No naming issues found" or a truncated report as if authoritative. Emit a `was_cancelled` flag alongside the payload and gate the UI response on it.
- **A `time.sleep(N)` "let the worker get going" delay before calling `cancel()` doesn't prove the worker is actually mid-scan — a slow test runner can let it pass even when cancellation only works between top-level items, not inside one.** (CodeRabbit, PR #325) Have the fake slow context set a `threading.Event` the instant its scan method is entered, and `.wait(timeout=...)` on that event before calling `cancel()`, instead of guessing a delay.
- **When a second background worker starts sharing a Cancel button/status label with an existing one, audit *every* handler that touches those widgets, not just the ones for starting/finishing the new worker.** (CodeRabbit, PR #325 — a second gap after the fix two notes above) `cancel_search()` and both workers' `finished` handlers were updated to know about both `_worker` and `_naming_worker`, but `clear_search()` — a third, pre-existing handler that also cancels a worker and hides `cancel_btn` — was missed. It kept cancelling only `_worker`, so clicking Clear while a naming check was running left it running with no visible way to cancel it, and able to still pop a report dialog after the UI had been cleared. Grep every reference to the shared widget/attribute across the file, not just the code path being actively edited.
- **`worker.cancel(); worker.wait()` doesn't stop an already-queued signal delivery from running afterward — and `disconnect()` alone does NOT fix this.** (CodeRabbit, PR #325, two rounds — the first fix was itself wrong) A worker's `progress_update`/`finished` are cross-thread queued connections: the worker can emit one before `wait()` returns, but `QThread.wait()` never pumps the event loop, so Qt only actually invokes the connected slot once the *caller* returns control to the event loop — by which point a blocking handler like `clear_search()`/`cleanup()` has already reset (or, in `cleanup()`, started deleting) the UI it touches. My first fix called `worker.finished.disconnect(slot)` right before `cancel()`+`wait()`, reasoning that Qt drops an already-queued delivery for a disconnected connection — **this is false**: per Qt's own docs, `disconnect()` only prevents *future* emissions from being queued; an event already posted to the receiver's queue still fires. It "worked" in testing only because that specific test's disconnect happened to land before the one-time `finished` emission occurred at all — it did not protect against a `progress_update` emitted earlier in the scan (already queued by the time `clear_search()` runs), nor against a genuine race where `finished` fires the instant before the disconnect call. The actual fix: give each scan a monotonically-incrementing id (`self._naming_scan_id`), capture it in the lambda that wires up each signal (`lambda status, sid=scan_id: self._on_progress(status, sid)`), bump the id when cancelling/tearing down, and have the slot itself compare the captured id against the current one and drop the call if they don't match. This is correct regardless of *when* the stale event was queued, and also closes a second gap disconnect-by-reference can't: a worker replaced by a new one before the stale callback arrives. Verified with a real-Qt test (`tests/test_tree_walk_cancellation.py`) that wires the worker up exactly the way production code does (not a simplified stand-in), confirmed to fail without the guard and pass with it.

- **Verify `lp` exists before calling it.** Use `shutil.which('lp')` rather than assuming the binary is on PATH.
- **Guard `QPrinterInfo.availablePrinters()` being empty.** Showing a print dialog with an empty printer list and OK enabled risks a crash or nonsensical job.
- **Prune failed pre-render items before the print pass.** If pre-rendering a page fails, remove it from the "to print" list too, or the same bad file is retried (and re-fails) during actual printing.
- **On toolbar-hook failure, still fall back — don't drop the files.** If an action can't be hooked, extend the OS-fallback list with the pending files instead of cancelling silently.

## Search / SQLite Index (JobDocs)

- **Escape LIKE wildcards in path-based queries.** Raw paths in a `LIKE` clause need an explicit `ESCAPE` char (e.g. `'!'`) to avoid matching unintended rows, especially with Windows `\` separators.
- **`os.walk` needs an `onerror` callback.** Without one, subdirectory read errors are silently swallowed and `completed` can end up `True` on partial results.
- **Track staleness recursively, not just on the top directory.** A single `getmtime` on a customer dir misses nested subdirectory changes; walk dirs (not files) for a lightweight recursive mtime check.
- **Don't commit partial index data from a cancelled walk.** Collect rows into a local list first; only delete + insert + mark-indexed after the walk actually completes.
- **Let index-query failures propagate, don't collapse them into "no match."** A caught `sqlite3.Error` returned as `None` is indistinguishable from a confirmed no-match; callers need to fall back to a filesystem scan on failure but trust `None` otherwise.
- **Don't treat a zero-result index query as automatic grounds for a filesystem fallback.** Check `indexed_dirs` coverage (shallow `os.listdir()`) to tell "confirmed zero matches" from "not caught up yet." Caveat: proves indexed *once*, not fresh — pair with the incremental-update note below.
- **Update the index incrementally on job/quote creation, don't rely on the background indexer alone.** It runs once per launch only. `SearchIndex.add_job()`/`add_quote()` insert one row right after a successful create so it's searchable immediately.
- **Every branch of a schema migration must force the same re-index, not just the "normal" path.** (CodeRabbit, PR #297) A v4 migration's "column already exists" fallback bumped `user_version` without clearing `indexed_dirs`, so already-indexed customers would never get the new column backfilled. Both branches of a conditional migration need the same side effects unless there's a real reason they shouldn't.
- **A coverage/freshness check can only validate containers it actually recorded.** (CodeRabbit, PR #316) `update()` derived `indexed_dirs` rows only from *discovered* jobs' ancestor paths — a PO folder matching the naming convention but currently empty was never recorded, so a job added there later went undetected by `is_fully_covered()`. Record every examined container, even ones holding nothing yet.
- **An incremental `INSERT OR REPLACE` upsert helper must write every schema column the full-index path writes, or it silently erases the omitted ones on the next call.** (CodeRabbit, PR #317 promotion review) `add_job()` omitted `po_number` from its INSERT; since it's keyed on `UNIQUE(prefix, path)`, calling it again for an already-indexed path replaced the whole row and SQLite filled the omitted column with its schema default `''`, wiping a real value `update()` had written. Diff the upsert helper's column list against the full-index INSERT's, not just against its own prior version.
- **Record a container as soon as it's recognized, not gated behind a check for something deeper inside it.** (CodeRabbit, PR #316 — a second gap in the fix directly above) The first fix still only appended `po_path` after confirming its expected subdirectory existed; a PO folder missing *that* stayed unrecorded too. Append on the outer match, before any nested existence check.
- **Distinguish a failed query from a confirmed zero-result before trusting cached coverage.** (CodeRabbit, PR #305) Calling `is_fully_covered()` right after a query helper returns `False` conflates "genuinely empty" with "the query itself errored" — and the index object it's called on may have just been set to `None` after repeated failures. Track a separate failed-flag; never dereference/trust coverage when it's set.
- **`os.path.join(base_dir, x)` preserves `base_dir`'s separator style; `pathlib.Path(...).parents` always normalizes to `\` on Windows.** Qt's `QFileDialog` returns forward slashes even on Windows, so a browsed `customer_files_dir` like `"Z:/Customer Files"` and a pathlib-derived container path for the same directory don't string-match — broke `update()`'s LIKE-prefix container lookup and `is_fully_covered()`, silently freezing the index for that customer forever after the first scan. `os.path.normpath()` every path before using it as a dict/set key or SQL LIKE input.
- **A path-normalization fix must be applied at every construction site of the same value, not just the one the bug report pointed at.** (CodeRabbit, PR #325 — a second gap in the fix directly above) The initial fix normalized `customer_path` where it feeds the per-customer staleness check, but missed a separate, earlier block in the same `bp_dirs` loop that also builds a `LIKE` prefix and a `valid_paths` set from the same raw `base_dir` — so a removed blueprint customer under a forward-slash root left an orphaned `indexed_dirs` row forever. Grep every use of the unnormalized variable in the function, not just the one in the reported code path.
- **A new diagnostic feature's README description must state its actual gating condition, not the general problem it happens to illustrate.** (CodeRabbit, PR #325) "Check Folder Naming" only scans PO-container layouts (`{po_number}` sharing a directory-name segment, e.g. `PO-{po_number}`) — the one branch of `find_job_folders()` with a naming convention to compare against — but the first README draft described it as a general job/PO naming check and claimed the flagged folders were "invisible to search entirely," when Search All Folders' uncached recursive walk can still find them. Match doc scope claims to the actual code gate, and verify "never/nowhere" claims against every search mode, not just the one under test.

## Build & Packaging

- **Quote shell paths containing special characters.** An unquoted `&` in a path acts as the shell background operator and breaks the command.
- **Guard destructive `rm -rf` on possibly-empty variables.** Use `${VAR:?message}` so an empty `BUILD_PATH`/`DIST_PATH` fails loudly instead of expanding to `rm -rf /`.
- **Check external tool availability before invoking it (e.g. `iscc`).** Don't depend implicitly on the hosted runner's preinstalled toolset; assert or install it explicitly.
- **Verify integrity of downloaded build dependencies.** Hash-check embeddable runtimes before use; prefer the already-installed system tool over an unverified network installer script (e.g. `get-pip.py`).
- **Derive version metadata from build variables, not hardcoded literals.** A hardcoded `FILEVERSION` in a `.rc` file drifts from the actual release tag over time.
- **Flatpak's `/app` is read-only at runtime.** Per-user writable state (installed plugins, deps) must go under `$XDG_DATA_HOME` / `~/.var/app/<id>/data`, gated on `FLATPAK_ID`.
- **When switching PyInstaller onefile to onedir, update every downstream consumer.** Flatpak staging, manifests, and verify steps all reference the old single-binary path and need updating together.
- **Manual recovery commands must use `sys.executable`, quoted.** Bare `pip` may resolve to the wrong interpreter; unquoted paths with spaces break copy-pasted commands.
- **Never run a built Inno Setup installer against a real machine's default paths to test it.** `[Setup] AppId` keys the Uninstall/Previous-Data registry entries regardless of `/DIR=`; a throwaway test install can still clobber a real install's registry data or PATH. Test with `iscc` syntax-compile only, or in an isolated VM/container.
- **Inno Setup: use `WizardIsTaskSelected`/task checkboxes, not `[Types]`+`TypesCombo`, for a simple binary install-variant choice.** `WizardForm.TypesComboChange` isn't a scriptable identifier in current Inno Setup; a Tasks-section checkbox plus `GetPreviousData`/`RegisterPreviousData` (not a global `PreviousDataKey`) is simpler and remembers the choice across updates.
- **Pre-select a `[Tasks]` entry via `WizardSelectTasks('name')`, never by matching its Description text.** Description strings get duplicated across `[Tasks]` and `[Code]`; if they drift, the match silently fails. `WizardSelectTasks`/`WizardIsTaskSelected` key off the stable `Name`.
- **A `[Tasks]` checkbox only hides files at runtime — the code is still on disk to unlock.** For a genuinely restricted variant (e.g. JobDocs Kiosk), ship it as a separate installer compiled from one parameterized `.iss` via `iscc /DFLAG script.iss` + `#ifdef FLAG`, with its own AppId/DefaultDirName so it coexists with and updates independently of the full app. Supersedes the two notes above for this use case.
- **An update-checker that auto-downloads a GitHub release asset by matching "first `.exe`" breaks once a release carries more than one installer.** (e.g. two product variants on one release) Match the asset by a distinguishing filename token specific to the running build instead.
- **Two product variants meant to coexist on one machine (separate AppIds) must not share a config/data directory.** (CodeRabbit, PR #315) Uninstalling either one wipes the shared directory, deleting the other's settings/history/local caches. Give each variant its own subdirectory (e.g. suffix the app name), keyed off the same single source of truth the variant-detection check itself uses — don't hardcode the path twice (once in app code, once in the installer's uninstall step) or they can drift.
- **A variant-identity check that reads a marker file written by a post-install `[Code]` script is user-deletable, even if that marker's original purpose (e.g. a UI toggle) seemed harmless to lose.** (CodeRabbit, PR #315) If the same check also drives something consequential (config-dir isolation, a persistence guard), deleting it breaks that too. Bake identity into the `[Files]` payload (`Source:` under `#ifdef VARIANT`) instead of `SaveStringToFile` in `CurStepChanged`.

## CI / GitHub Actions

- **Only grant `contents: write` to the job that actually publishes a release.** Build/upload-only jobs need `contents: read`.
- **Pin CI dependency versions to match `requirements.txt`.** Don't duplicate a looser version constraint directly in workflow YAML.
- **Add a stable-ancestry guard on tag-triggered release workflows.** Verify the tag's commit is an ancestor of the correct branch before building/releasing.
- **Order artifact upload before any signing step.** The signing action reads from an already-uploaded artifact.
- **Pin the pip bootstrap; don't rely on `-latest` runner images.** Use `actions/setup-python` with a pinned version and a pinned `pip==` release for reproducible builds.
- **`ci.yml`'s "Tests" job runs on `ubuntu-latest`, not Windows** — the only job that runs `pytest` at all; `Build (Windows)` never does. A test asserting Windows-only `os.path` semantics (drive letters, `\` separators, case-insensitivity) with a hardcoded `r'C:\...'` literal silently exercises meaningless `posixpath` behavior there instead of failing loudly — verify locally with the real thing (WSL, or `platform.system()`) before trusting it passed for the intended reason. Build such tests on real `tmp_path` dirs (portable) and `@pytest.mark.skipif(os.name != 'nt', ...)` the genuinely OS-only cases.
- **Run flake8 locally with CI's *exact* flags, never a bare `flake8 <file>`.** CI's "Lint & Security" job runs `flake8 --max-line-length=120 --select=E,F --exclude=.git,__pycache__,build_scripts,linux .` (check `.github/workflows/*.yml` for the current exact command, don't assume). A bare local `flake8 <file>` uses flake8's own default 79-char limit, producing a wall of E501s on normal code — an entire session's worth of local "flake8 clean" checks were done by filtering those out with `grep -v E501`, on the wrong-but-plausible assumption they were all pre-existing noise below CI's real (120-char) threshold. Three lines in a new file were genuinely 148-300 characters, well past even 120, and shipped straight to a real CI failure since the filtered local check could never have caught them. Also exclude local-only gitignored dirs (`deps/`, `dist/`, `test_cli*.py`, etc.) that don't exist in CI's clean checkout but do exist on a dev machine and would otherwise drown real findings in irrelevant noise — or scope the check to `git ls-files '*.py'` instead of `.` to sidestep the exclude-list question entirely.

## Plugins & Dynamic Loading

- **Register a plugin's parent package in `sys.modules` before `exec_module`.** External plugins using relative imports (`from .helpers import ...`) fail without a registered parent package with `__path__` set.
- **When the parent package is already registered by something else, extend its search path — don't just leave it alone.** (CodeRabbit, PR #334) If `plugins` was already in `sys.modules` (e.g. a real namespace package Python discovered via cwd) with a `__path__` that excludes the configured `plugins_dir`, leaving it untouched means an unregistered sibling plugin in `plugins_dir` can never be found through it. Append the missing directory to the existing object's `__path__` (reassign, don't mutate in place — works for both plain lists and `_NamespacePath`) instead of skipping registration entirely once `"plugins" in sys.modules` is true.
- **`core/module_loader.py`'s dev-mode path loads built-in modules via `spec_from_file_location` under the exact same dotted name as the standard package import (`modules.<name>.module`).** If that code path runs mid-test-session, it can register a second, distinct module object at that `sys.modules` key. A test that does `unittest.mock.patch('modules.<name>.module.Thing')` (a string lookup resolved at patch time) can silently patch the wrong copy — one the real class's methods don't read from — while assertions on non-invocation pass trivially. Patch the target function's own `__globals__` dict directly instead; it's correct regardless of which module object `sys.modules` currently holds.
- **Move blocking I/O off the GUI thread.** Network downloads and zip extraction during plugin install must run in a `QThread` worker, not the main thread.
- **In frozen apps, try the bundled interpreter before falling back to system Python.** ABI mismatches between bundled and system Python can break binary wheels.
- **Invalidate any startup-computed module cache on install/uninstall.** A `discover_modules()` result cached once at startup (e.g. for a Settings dialog list) goes stale the moment a plugin is installed/uninstalled mid-session; recompute it in both success handlers, not just at launch.

## Reporting Module (JobDocs)

- **A fixed, predictable default export filename (not a timestamp) needs a uniqueness guard wherever it's reused for a path the app writes to without asking, not just the Save dialog's suggestion.** `export_report()`'s old `report_20261021_120144.xlsx`-style name was accidentally always-unique; switching to `JD_<ReportName>.xlsx` (e.g. "Job Report" -> "JD_JobReport.xlsx", via `_default_export_filename()`) is exactly what was wanted for the Save dialog's suggested name, but the SAME variable was also reused verbatim for the 'app' destination's temp file path -- re-exporting the same report type twice in a row (a normal "re-check after a fix" workflow) would reuse the identical temp path and fail with a permission error if the first export was still open in Excel. Fixed by keeping the clean name for the Save dialog only, and appending a `HHMMSS` suffix just for the temp-file path. When a "make the filename nicer/more predictable" request removes an accidental uniqueness property, check every call site that relied on it, not just the one the request was about.
- **A new report type in Reports (Beta) is one file under `modules/reporting/reports/`, not a new branch in `db_integration.py`/`module.py`.** Each file builds a `ReportDefinition` (query/formatter/columns/headers/filter flags, see `base.py`) and registers it in `reports/__init__.py`'s `REPORTS` dict; `module.py`'s generic glue reads those flags, so no per-type `if`/`elif` is ever added there. Check every new `ws.append(...)`/`writer.writerow(...)` call against JobBOSS-sourced data for this, not just the ones that look like "the main export path."

The lesson: "Active Employees Only" governs which employees get their own *row* in the output, not whose hours get pooled into a shared calculation for employees who do — two independent things that looked like the same population until checked with an exact number. When a user pushes back with "something's still off" on a formula this module has already "confirmed," re-derive from one concrete operation rather than trusting the existing docstring's prior conclusion.
- **An aggregate accuracy percentage can't localize a bug — pick one real row and solve for the missing total algebraically.** The technique that found the Active-employee bug above: given a real `Adj Hrs` value and a known `Est Hrs`, solve `Total = Est * Act / Adj` for what denominator *would* produce the real answer, then go find out whether that number corresponds to something real (a specific subset of contributors, a date cutoff, etc.) rather than guessing formula variations. Also exposed a real gap in a from-scratch comparison script: matching rows between two exports by `(Job, Work_Center, Operation_Service)` text silently keeps only the last of any duplicate-labeled Job_Operation (a dict overwrite) — filter out any text key that appears more than once in the reference export before trusting a bulk diff, or results get contaminated by the same descriptive-triple-isn't-unique problem already documented elsewhere in this file.
- **A live JobBOSS report export is a snapshot, not a live view — know when it was generated before trusting a number it disagrees with.** One specific operation's real `Adj Hrs` didn't fit under any denominator computable from today's live data; re-exporting the same JobBOSS report confirmed the number was unchanged (not stale data), but a second, differently-configured export (this time without "Active Employees Only" checked) surfaced the *other* contributors' own rows for the same operation — which showed all contributors getting an identical equal split of `Est Hrs` regardless of actual hours logged, not proportional share at all. Two "unexplained dead end" operations from earlier in this investigation turned out to fit this same equal-split pattern retroactively once it was known to look for. When a single operation resists every formula tried, getting a second export with different report options (here: Active-only unchecked) can surface additional ground-truth rows that explain it, rather than assuming the first export answers every question. **Correction, found one session later:** the "predates Data Collection module" explanation given here at the time was wrong — a follow-up investigation ran the equal-split-vs-proportional split by year across the *entire* history and found equal-split operations at a similar rate in 2026 as in 2010, no date/job-number cutoff anywhere. The original explanation was never actually checked against more than the 2 operations that prompted it; it just sounded plausible and matched the "old data is noisier" pattern already established elsewhere in this same investigation. Don't let a plausible-sounding explanation that fits 2 data points graduate to "confirmed" without checking it against the full dataset the same way everything else in this formula was checked.
- **An exhaustive, failed search for a trigger condition is still a valuable result — write up what was ruled out, not just what wasn't found.** Chasing the equal-split trigger above: every `Job_Operation` column was checked for separating power, two genuinely *necessary* (not sufficient) conditions were found and confirmed with zero exceptions across thousands of rows, and one real job was found with two operations sharing every checked attribute while landing on opposite sides of the split — which proves the trigger isn't recoverable from this module's visible data, not just that it wasn't found yet. That proof is worth exactly as much as finding the trigger would have been, because it stops a future session from re-running the same failed search. Documented as "what the trigger is NOT," not left as a bare "couldn't figure it out."
- **A rule that's right half the time is worse than no rule.** The best available trigger for the equal-split pattern above (two necessary conditions combined) was only ~49% precise — implementing it would have converted about as many currently-correct rows to wrong as it fixed, for a net accuracy gain of +0.28 percentage points. Measure a candidate rule's *net* effect (rows it fixes minus rows it breaks) before shipping it, not just whether it explains the specific examples that motivated it — a rule can be real (JobBOSS's own Crystal recordset does carry an `EmpCount` field confirming the branch exists) without being something this module can reconstruct well enough to use.
- **`int(value)` on an export cell silently discards a real leading zero.** (CodeRabbit, PR #344) `_numeric_or_text()` converted any digit-only string via bare `int()`/`float()`, so a PO/part number like `"0012345"` landed in xlsx as `12345` — a lost digit, not a display artifact. `float()` itself also accepts `"nan"`/`"inf"`/`"1e5"`, which could silently turn literal text into a special float. Fixed with a narrow `^-?\d+(\.\d+)?$` regex gate, plus an int round-trip check (`str(int(value)) == value`) so a value only converts if nothing was lost — `"30309"` (no leading zero) still converts, `"0012345"` stays text.
- **`openpyxl`'s `ws.max_row` is computed from populated cells, not rows appended -- `ws.append([])` (an empty-list row, e.g. a blank spacer before a trailing summary row) does NOT advance it, even though it does occupy a real row.** `_write_xlsx_report_sheet()`'s Department Average block computed `avg_row_idx = ws.max_row + 1` immediately after `ws.append([])`, landing one row too early (on the blank spacer itself) -- so the bold-font styling, and later a percentage number-format, were silently applied to the wrong (empty) row and never actually reached the real average row. Found only because a new test checked `cell.font.bold`/`cell.number_format` directly instead of just the row's values (the existing test only asserted `['Department Average', '', 15.0] in values`, which can't detect a styling-only bug). Fixed by reading `ws.max_row` AFTER appending the real row instead of before -- that row always has actual content, so the gap can't recur. When styling a row appended after a deliberately-blank spacer row, never precompute its index from `max_row` taken before the real append.
- **An export feature that inserts non-data rows (a per-group total, a spacer) into `data_rows` breaks the Excel Table/AutoFilter wrapper, which requires every row in its range to be real, uniformly-shaped data.** `ReportDefinition.uses_employee_total_rows` (Detail's per-employee "<Employee> Total" + blank spacer rows, matching JobBOSS's native block-per-employee layout) has to skip `_write_xlsx_report_sheet()`'s Table-building step entirely when this flag is set, trading away AutoFilter/sort for that report type rather than building an invalid Table range. Also: the inserted total row must use the same string-formatted values (`f"{x:.2f}"`) every other cell in `data_rows` uses — `_numeric_or_text()` assumes a string input throughout this pipeline and crashes (`TypeError`) on a raw float, caught by a test before it shipped.
- **A blank-cell exclusion rule implemented only at the per-cell level doesn't automatically apply to an aggregate SUM() built on top of it.** `op_scored`'s CASE guards (Employee Efficiency Summary) correctly NULLed `Setup_Adj_Hrs`/`Run_Adj_Hrs` for an unscoreable operation, but left `Setup_Act_Hrs`/`Run_Act_Hrs`/their Est Hrs counterparts unguarded — real logged Act Hrs from an unscoreable op (e.g. a `Work_Center.Type='Direct'` monthly overhead-bucket job, not caught by the existing Indirect-type exclusion) still inflated the outer `SUM()` denominator even though it contributed nothing to the numerator. One real case: JobBOSS's own report showed 136.99%, this module showed 0.6% — the denominator diluted ~220x by unscoreable hours. Fixed by wrapping all four Act/Est columns in the same CASE guards as Adj Hrs. When a per-row NULL-for-"not applicable" convention feeds an aggregate, every column going into that aggregate needs the same guard, not just the one whose blankness is visually obvious.
- **An averaged column needs to know it's actually a metric, not just that every value in it happens to parse as a number.** (CodeRabbit, PR #344) `_department_average_row()` averaged any all-numeric column with no concept of "this is an identifier" — a Job/Operation column that's all bare numbers would get a meaningless average. Separately, voiding the *entire* column average on the first unparseable cell conflated a genuine anomaly (stray text) with an expected blank (an Indirect operation's not-scoreable Adj Hrs) — the latter should be excluded from that column's average, not blank the whole thing. Fixed with `ReportDefinition.average_columns` (explicit allow-list of metric column keys, empty by default) plus treating `''` specifically as "exclude this cell," while any other non-numeric value still voids the column.

## Real-Data Leak Prevention Tooling (JobDocs)

- **A `git diff` subprocess call must disable color explicitly, not just rely on the caller's default config.** (CodeRabbit, PR #344) `pre_commit_check.py` parsed `git diff --cached` output by matching literal `+++ `/`+` line prefixes; a developer with `color.diff=always` set would get ANSI escape codes prepended to those lines, breaking the match and letting a real employee identifier through the hook undetected. Pass `--no-color` explicitly on any diff output a script parses structurally — never assume a clean default.
- **`command -v <interpreter>` proves a name resolves on PATH, not that running it actually works.** (CodeRabbit, PR #344) `tools/githooks/pre-commit`'s `py`/`python3`/`python` fallback chain checked existence only; on this machine, `python3`/`python` resolve to the Microsoft Store's non-functional redirect stub, which exists on PATH but errors when run. Combined with `set -e`, a broken-but-present candidate ahead of a working one in the try-order would abort the whole hook instead of falling through. Fixed with a `_works()` probe (`command -v "$1" && "$1" -c "import sys"`) that actually invokes the candidate before trusting it.
- **A gitignored cache file holding real HR data needs restrictive permissions, not just `.gitignore`.** (CodeRabbit, PR #344) `generate_sensitive_identifiers.py` wrote `.claude/sensitive_identifiers.txt` with default permissions, readable by any other local account on a shared machine. `os.chmod(path, stat.S_IRUSR | stat.S_IWUSR)` after writing narrows this on POSIX; note it's a no-op ACL-wise on Windows (chmod there only toggles the read-only attribute) — document the limitation rather than overclaiming protection the platform doesn't actually provide.

## JobBOSS DB Connection Docs (JobDocs)

- **A UI label or docstring describing "what this login can access" drifts from the real grant script the moment the script changes.** (CodeRabbit, PR #344) `settings_dialog.py`'s advanced-settings label said "SELECT-only access to the Job table" after the real README grant script had grown to 6 tables (Job/Delivery/Job_Operation/Job_Operation_Time/Employee/Work_Center) for Employee Efficiency — a user granting access from just the label's wording would under-grant and silently break two report types. When a grant script's scope changes, grep for every place that *describes* it in prose, not just the script itself.
- **"Set env var X alone to do Y" is only true if X is actually sufficient on its own — verify the other fields don't also need to change.** (CodeRabbit, PR #344) `dump_db_schema.py`'s `_load_settings()` docstring documented `JOBBOSS_DB_PASS` alone as the way to "run with a different, broader login" — but the username also has to change (`JOBBOSS_DB_USER`), or the new password is tried against the still-stored old username and fails. Also fixed: an env var *set* to `''` (vs. not set at all) now actually clears a stored value (e.g. `JOBBOSS_DB_PORT=''` to drop a stale named-instance port when overriding just the host) — the merge loop previously treated both cases identically via a falsy-string check (`if value:`), checked via `if env_var in os.environ` instead.
- **`GRANT VIEW DEFINITION ON DATABASE` exposes more than table/column metadata.** (CodeRabbit, PR #344, Major/Security) `dump_db_schema.py`'s module docstring described this grant as exposing "just table/column names and types," but it also makes `sys.sql_modules` readable — the full T-SQL source of every view, stored procedure, function, and trigger, which can itself contain sensitive business logic. Don't describe a metadata-visibility grant as metadata-only without checking what `sys.sql_modules`-style catalog views it also unlocks.

## Update Checker

- **Strip pre-release suffixes before parsing a version tuple.** `"v0.9.9-test".split('.')` throws; split on `-` first.
- **Only emit a positive result on confirmed success.** Catch specific exceptions (`URLError`, `JSONDecodeError`, etc.) — a bare `except: pass` around a version check can report "up to date" on a network failure.
- **Join/interrupt background threads before the app exits.** Otherwise Qt logs "QThread: Destroyed while thread is still running."
- **Guard against launching duplicate background checkers.** Check `existing.isRunning()` before starting a new one from a menu action.
- **Gate Flatpak-only code paths on `FLATPAK_ID`.** Don't attempt `flatpak-spawn` (or similar) unconditionally on all Linux — it fails silently outside the sandbox.
